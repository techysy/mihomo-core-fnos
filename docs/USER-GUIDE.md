# Mihomo Core 使用说明

> 状态页 `http://<NAS-IP>:9092` · 代理端口 `7890` · Clash API `9090`

## 快速上手

1. **App Center 安装** mihomo-core，安装后自动启动（自启服务）
2. 打开状态页确认 Clash API 显示「在线」
3. 配置订阅（见下）或手动导入节点配置
4. 局域网设备代理地址填 `http://<NAS-IP>:7890`

## 订阅配置

**入口：App Center → mihomo-core → 应用设置**

| 字段 | 说明 |
|---|---|
| 订阅名称 | 自定义名称（如 机场A），留空自动命名 |
| 订阅链接 | 机场订阅 URL（clash 格式） |

保存后自动拉取订阅并热重载内核。状态页「订阅」行点击可手动重新获取。

> - 订阅以**完整配置模式**生效（节点 + 规则 + 分组全按订阅内容）
> - 每次更新订阅会自动强制 `allow-lan: true`、端口 7890 / API 9090（防止订阅默认值断开局域网代理）
> - 首次配置后打开状态页会自动获取一次

## 内核热更新（v1.1.2 新增）

状态页「内核版本」行显示当前版本（橙色可点击）。点击 → 确认后自动：

```
GitHub 查最新版 → 下载 → 解压校验 → 原子替换二进制 → 重启内核进程
```

- 全程约 10~60 秒（取决于网络），期间代理中断几秒
- 结果就地显示在版本号行：绿=成功 / 红=失败，3 秒后自动恢复
- **任何一步失败都不会动原内核**，重试即可
- 已是最新版本时会提示"已是最新"
- 注意：App Center 升级 fpk 会把内核恢复为打包时版本，热更新适用于两次发版之间快速跟进上游

## 状态页各项说明

| 项目 | 含义 | 操作 |
|---|---|---|
| Clash API (:9090) | 内核在线状态 | — |
| 内核版本 | 当前 mihomo 版本 | 点击 = 检查并更新 |
| 模式 | rule/global/direct | 面板切换 |
| 节点数 | 加载的节点总数 | — |
| 规则数 | 分流规则数 | — |
| 订阅 | 订阅状态与节点数 | 点击 = 手动获取 |
| 混合代理端口 | 固定 7890 | — |

页面底部有 MetaCubeXD 面板下载入口和 API 地址复制。

## 配合 MetaCubeXD 面板

1. 未安装：点状态页底部橙色 "MetaCubeXD" 下载
2. 面板中添加 API：`http://<NAS-IP>:9090`
3. 切换节点 / 测延迟 / 看连接均在面板操作

## 常见问题

| 现象 | 处理 |
|---|---|
| 更新订阅后局域网设备断网 | v1.1.2 起已自动强制 allow-lan: true；旧版本请手动检查 config.yaml |
| 状态页打不开 | App Center 重启应用；确认 9092 端口未被占用 |
| 内核更新提示"下载失败" | GitHub 直连偶发中断，直接重试一次；原内核不受影响 |
| 更新后内核还是旧版 | fpk 升级会还原打包时内核，重新点击热更新即可 |
| 订阅获取失败 | 检查链接有效性；确认 NAS 能访问订阅地址 |

## 数据目录

```
/volN/@appdata/mihomo-core/
├── config.yaml          # 运行配置（订阅更新会重写）
├── subscription_url     # 订阅配置（名称|链接）
├── geoip.metadb         # IP 库
├── cache.db             # 内核缓存
└── mihomo.log           # 运行日志
```

卸载应用不会删除数据目录；完全清除需手动删除该目录。
